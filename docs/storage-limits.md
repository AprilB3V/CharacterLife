# 快照存储与空间维护

`saveSnapshot()` 按实例保留最多 32 份完整恢复快照。同一 UTC 墙钟时间的
5 分钟区间内更新最新快照，跨区间新增快照。每次调用仍保存最新 runtime、
模拟时间、事件序号及关系状态，不依赖事件序号是否变化判断状态是否变化。
更新/新增和保留清理位于同一事务，失败时一并回滚。

此限制仅作用于 `snapshots`。最新状态、角色记忆、事件、审计账本、会话、
平台绑定与上下文统计不受此保留策略清理。快照数量有上限不代表整个数据库有固定大小。

## 已有大库

不要在空间不足时直接启动新版本清理十几万份旧快照，也不要直接执行 VACUUM。
先停止所有使用此库的服务，再生成独立候选库：

```powershell
python scripts/compact-storage.py data/jingjing-video/characterlife.db data/jingjing-video/characterlife.optimized.sqlite
```

工具以一致的只读事务读取原库，逐表复制并校验记录摘要；仅对快照按实例保留
最新 32 份。它保留 schema、索引、触发器、视图、AUTOINCREMENT 高水位和版本参数，
并检查候选库完整性与外键。成功后生成 `*.verification.json`。工具不会自动替换原库。
失败时原库不变，未完成的候选库不可用于切换。

切换前须保持所有写入进程离线，再次确认候选库验证报告，完成原库 WAL checkpoint
并关闭连接。保留原库及必要 WAL 作为回退备份，然后将候选库改为正式库名。
切换后验证角色恢复和最新快照。备份的逻辑文件大小与实际磁盘占用可能因 NTFS 压缩不同。

当前开发代码与鲸鲸服务实际使用的内核副本均需包含本次修复；更新子模块时应保留该改动。
