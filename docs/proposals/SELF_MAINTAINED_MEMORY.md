# 自维护记忆（提案 · 草案 v0.1）

> **状态：设计草案，未实现，不构成实施承诺。**
> 2026-11-04 在网页对话中与主导者讨论形成。按 TodoList 的原则「先评测，后改架构」，
> 本提案的任何实现都要等 CL-001 / CL-002 给出失败证据后再决定（对应 TodoList CL-015）。
> 文中提到的现有机制均按 `main`（v0.7.0 之后）核对过；与代码冲突时以代码为准。

## 0. 一句话

**记忆的维护应该是角色自己发起的动作，而不是一条作用在她身上的人工流程。**
主导者写内核（世界的规则），角色住在用户态（自己的记忆）。
人的角色从「逐条审批」变成「定规则、回答疑问、审计与回滚」——引导，而不是决定。

## 1. 要解决的问题

现在记忆的「维护」主要靠人或固定规则：

| 环节 | 现状 | 出处 |
|---|---|---|
| 模型提出的记忆 | 进待审队列，人批准后才写入 | CL-012，`src/console/` |
| 冲突 | 检测后标 `unresolved`，只有显式 `supersedeMemory()` 才处理 | MEMORY_ARCHITECTURE §4 |
| 反思 | **不做**：Mind 的想法只进日志，避免未经证实的自述进入长期记忆 | AUTONOMY §7 |
| 容量 | 超过 `MAX_ENTRIES` 按低价值淘汰 | `src/kernel/memory/store.ts` |
| 摘要 | 每轮取首句 40 字 | MEMORY_ARCHITECTURE §9.2 |

这些选择在当时是对的：它们挡住了「模型自述冒充事实」。代价是角色不会自己整理经历、
不会因为发现矛盾而产生疑问、也不会把零散观察总结成规律。
长期运行（直播、箱庭、斗场）时，人工审批跟不上，规则淘汰又太粗。

本提案的目标：**让角色自己维护记忆，同时不放松「意图 ≠ 事实」这条底线。**

## 2. 已经具备、不需要重做的基础

- **账本（K2 / K3）**：只追加的哈希链，世界事实只能由登记过的权威签发。这就是下文的「第一层真值」。
- **记忆行的认识论字段**：`status`（fact / speculation / fiction）、`origin`、`trust`、`confirmed`、`sourceRef`。
- **持久层守卫**：`untrusted ⇒ speculation`、`confirmed ⇒ kind=user` 等在持久层强制成立。
- **提议—裁决通道**：所有持久状态改变经 PolicyEngine，审计带语义标签。
- **驱力只能由运行时写**（AUTONOMY 不变量 14）：动机研究那份提案沿用这条。

所以缺的不是存储，而是**一组让角色自己操作记忆的受控入口**，以及**触发它们的理由**。

## 3. 两层真值

```
第一层：账本（只读给角色）
  世界事实（权威签发）· 原始观察 · 用户原话 · 模型原始输出
          │ 引用（cites）
          ▼
第二层：角色记忆（角色可改，派生视图）
  情景 · 信念 · 对人的认识 · 自述（日记）
```

- 第一层是**经历过什么**，角色只能读，不能改。
- 第二层是**她怎么理解这些经历**，完全归她维护。
- **每一条角色自己写的记忆都必须引用第一层的记录**（`cites: ledgerRecordId[]`）。
  没有引用，就是凭空出现的记忆——自维护记忆最大的风险是**虚构记忆（confabulation）**：
  记得没发生过的事，再自我强化。引用要求从结构上挡住它。
- 因为第二层是派生的，**任何时候都能从账本重建或回滚**，不需要人去逐条改记忆。

这与现有 `sourceRef`（单条出处）兼容：`cites` 是它的复数形式，旧记忆的 `sourceRef` 视为单元素 `cites`。

## 4. 记忆系统调用

角色在思考阶段或反思阶段调用下列操作。每个调用都是一条**提议**，经 Policy 裁决、写审计、进账本。

| 调用 | 作用 | 备注 |
|---|---|---|
| `remember(content, cites, importance, feeling)` | 写一条新记忆 | 默认 `status=speculation`，`origin=character_inference` |
| `revise(id, content, reason, cites)` | 改写自己写过的记忆 | 旧版本留在账本（K3），记忆行只保留新版 |
| `link(a, b, relation)` | 建立两条记忆的关系（因果、同一人、矛盾…） | 供检索扩展与冲突发现 |
| `archive(id, reason)` | 遗忘 = 归档 | **不是删除**；删除仍只属于 Runtime / Owner（现有权限矩阵不变） |
| `doubt(id, question)` | 把一条信念标为存疑 | 产生「想问」的压力，见 §6 |
| `reflect(scope)` | 把一段经历总结成更高层的看法 | 产出仍是 `speculation`，引用被总结的记忆所引用的账本记录 |

### 4.1 内核检查（每个调用都要过）

| 检查 | 规则 | 理由 |
|---|---|---|
| 必须引用 | `cites` 非空，且每条都存在于本实例账本、对本角色可见 | 挡住虚构记忆 |
| 认识论上限 | 角色自写的记忆最高是 `speculation` | 理解不等于事实；升级见 §4.2 |
| 信任传递 | 引用了任何 `untrusted` 来源，结果也是 `untrusted` | 注入不能经「总结」洗白 |
| 不碰确认过的记忆 | `confirmed=true` 或 `origin=user_confirmed` 的记忆不能 `revise` / `archive`，只能 `doubt` | 用户说过的话角色可以怀疑，但要去问，不能偷偷改 |
| 不碰 Self | 人格只读（K1），角色自述写在记忆里，不写 `profile` | 自我认识可以变，身份指纹不变 |
| 频率上限 | 每模拟小时、每会话的写入与改写次数有上限；同一条记忆的改写次数有上限 | 一次情绪化的反思不能改写整个世界观 |
| 只能改自己写的 | `revise` / `archive` 只对 `origin=character_inference` 的行生效 | 世界记忆与用户记忆的出处不能被覆盖 |

### 4.2 推测怎么变成事实

角色不能自己把推测升级为事实。升级只有两条路：

1. **用户确认**：对 `doubt` 产生的问题，用户给出回答 → 新记录 `origin=user_confirmed`。
   扩展可以配置「用户的话是权威」（例如视频搭档），这是扩展的策略，不进内核。
2. **世界确认**：推测的内容被后续世界事实直接证实（由扩展提供判定，形状同承诺账本的 `criterion: { kind, params }`）。

## 5. 什么时候维护：三种节律

不靠定时任务，而是复用现有的 Waker 与会话边界：

| 节律 | 时机 | 做什么 | 谁来做 |
|---|---|---|---|
| 在线 | 每次 Mind 被唤醒时 | 顺手 `remember` / `doubt`，标记「这件事重要」 | Mind（模型），作为 `MindDecision` 的附带输出 |
| 空闲 | 没有外部输入、未整理的经历累积到阈值 | `reflect` 最近一段，形成假设 | Mind，由一个新的唤醒理由触发（见 §11 问题 2） |
| 睡眠 | 会话结束 / 箱庭一天结束 | 合并重复、衰减久未使用的、把反复被检索的提升为常驻；写日记 | 确定性部分由 Runtime 做；总结部分由 Mind 做，仍受 §4.1 约束 |

「睡眠」里确定性的部分（去重、衰减、提升）不调用模型，结果可重放；
需要语言理解的部分（总结、日记）调用模型，输出入账（K4）。

### 5.1 防抖动

同一条记忆在短时间内被反复检索调入，说明它属于当前的「工作集」，
睡眠时应把它提升到常驻层（更高 salience 或进入每轮固定注入），而不是每轮重新检索。
这是操作系统「抖动」问题在记忆上的对应。

## 6. 疑问（doubt）变成提问的动力

- 未解决的 `doubt` 进入 Mind 输入的 Memory 槽（「我不确定的事」）。
- 未解决疑问的数量形成一个**认识压力**读数，像驱力一样参与唤醒与行为选择
  （形式见 [`MOTIVATION_V2.md`](MOTIVATION_V2.md) §5）。
- 压力够高时，角色会**主动**在合适的时候问出来。
  主导者只需要回答，规则就由她自己写进记忆——这就是「引导而非决定」在工程上的样子。

## 7. 对 AUTONOMY §7「不做反思」的修订（提议）

原约束的目的是不让未经证实的自述进入长期记忆。本提案保留目的、换掉手段：

- 反思可以写入记忆，但**只能是 `speculation`、必须带引用、必须过 §4.1 全部检查**；
- 反思不能升级认识论状态，不能改写用户确认过的记忆，不能触碰 Self；
- 修订本身需要主导者同意，并在 DECISIONS 追加一节。

## 8. 人的位置：从闸门到审计

| 模式 | 行为 | 何时用 |
|---|---|---|
| `gate`（现状，默认） | 模型提出的记忆进待审队列（CL-012） | 评测指标未达标前 |
| `audit` | 角色直接执行记忆调用；后台展示变更日志（diff）、可按账本回滚 | §9 的指标达标后，由主导者切换 |

`audit` 模式下人的手段：
- 说的话（权威来源）；
- 回答她的疑问；
- 宪法与 Policy（内核）；
- **只读的记忆变更日志**；
- **回滚**（只经内核，从账本重建到某个序号）。

## 9. 怎么知道它在起作用（接 CL-001 / CL-002）

切换到 `audit` 之前，用 CL-001 的评测集跑以下指标：

| 指标 | 含义 |
|---|---|
| 引用有效率 | 自写记忆中引用全部有效、且内容能被引用支持的比例 |
| 虚构率 | 找不到支持事件的记忆比例（人工抽检） |
| 归属正确率 | 说话者 / 被提及对象 / 主客体是否记对（CL-001 的核心指标） |
| 矛盾数 | 同时相信两件矛盾的事的次数 |
| 疑问解决时延 | 从 `doubt` 到被确认或推翻的时间 |
| 检索有用率 | 调入的记忆被实际用于回答或决策的比例 |
| 身份稳定 | 身份指纹不变；固定人格测试题跨会话一致 |

## 10. 与上下文窗口的关系

这套分层与操作系统的存储层次一一对应，也给现有 `ContextManager` 提了两个改进方向：

| 层 | 内容 | 现有对应 |
|---|---|---|
| L0 钉住 | 人格、宪法、规则 | 受保护 system 块（永不压缩，已实现） |
| L1 工作集 | 处境、最近观察、最近 N 轮 | 最近轮次 + 本轮记忆 |
| L2 会话摘要 | 本场发生了什么 | 历史摘要（现为首句 40 字） |
| L3 长期 | 情景、信念、对人的认识 | MemoryStore + 检索 |

改进方向（各自独立，可单独评测）：
1. **水位线**：现在的四阶梯降级在溢出时才动作；改为用到约 60–70% 时在后台整理（写回 L3、更新 L2），而不是等到裁剪。
2. **按处境检索**：`rankMemories` 现在以本轮文本的词面重合为主（0.45）；
   在游戏或箱庭里，「此刻发生什么」比「刚说了什么」更能决定该想起什么。
   可以增加一项以 Situation 为查询的分数，并在处境变化时预取。

## 11. 未决问题

1. `cites` 引用账本记录时，被「被遗忘权」擦除了内容本体的记录（K3 墓碑）怎么办：引用它的记忆一并归档，还是保留看法、丢掉出处？
2. 空闲反思需要一个唤醒理由。是新增 `WakeReasonKind`（如 `consolidate`），还是把认识压力当作一条派生驱力复用 `drive`？后者改动更小。
3. `MindDecision` 增加 `memoryOps` 字段会改变 LLM Mind 的输出协议，旧录制（ReplayProvider）会作废。
4. 多角色（Free Roam）里，角色 A 能否引用「角色 B 对自己说的话」：这是 B 的 `agent` 来源观察，按 KERNEL §6，可见性是世界规则。
5. 频率上限的具体数值需要 CL-001 的数据。

## 12. 建议的实施顺序

1. CL-001 / CL-002 先给出现有记忆的失败证据（不改代码）。
2. `cites` 字段与引用检查（纯增量，旧数据视 `sourceRef` 为单元素）。
3. `remember` / `doubt` 两个调用 + `gate` 模式下进待审队列（行为与现状一致，只是入口变成角色自己）。
4. 睡眠中的确定性整理（去重、衰减、提升），可重放。
5. `reflect` 与 AUTONOMY §7 的修订（需主导者同意）。
6. 指标达标后试 `audit` 模式。
