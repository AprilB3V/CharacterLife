# CharacterLife 宪法 · 完整性微内核（草案 v0.1）

> 状态：**V0.6 已实现**（`src/kernel/integrity/`），实现与测试的对照见 §8。
> 本文定义一组跨世界通用、可以被测试断言的完整性不变量。CL 的 Runtime、CL-World，
> 以及建立在 CL 上的任何节目或游戏（例如 Free Roam），都是这组条款的使用者。
> 现有代码中已经成立的部分见 §5 对照表。

---

## 0. 定位

**完整性微内核**回答一个问题：一个角色经历过的事，事后能不能被信任。

它只管四件事：谁是谁、什么算发生过、发生过的能不能改、看不见的东西能不能事后核对。
它不管角色怎么说话、关系怎么成长、世界有什么规则——那些属于外层模块和各个世界。

内核的设计约束：

1. **零依赖、纯数据与纯函数**：不调用模型，不读提示词，不做网络或文件 I/O。
2. **不可信输入不能提升权限**：沿用 `src/kernel/policy/policy.ts` 的原则，权限来自 actor 身份，绝不来自内容。
3. **安全失败**：违反条款时拒绝并留痕，调用方继续运行，而不是崩溃。
4. **只能加严，不能放宽**：世界和外层模块可以在内核之上加更严格的规则，不能削弱任何一条。

## 1. 术语

| 术语 | 含义 |
|---|---|
| 角色 | 一个有核心设定的 CL 实例。核心设定即 `CharacterProfile` |
| 身份指纹 | 角色核心设定的规范化哈希，代表“这个角色是谁” |
| 权威 | 被登记为可以确立某类事实的 actor，例如 CL-World、某个节目的规则引擎 |
| 意图 | 任何人（含模型）提出的“想做什么”，本身不改变世界 |
| 事实 | 由权威签发、记入账本的“确实发生了什么” |
| 账本 | 只增不改的记录序列，每条记录链接前一条的哈希 |
| 种子流 | 登记过名称与种子的确定性随机数来源 |
| 承诺 | 隐藏内容的校验码 `sha256(salt \| 内容)`，揭示前只公开校验码 |
| 预先登记 | 在第一个结果产生之前，把会影响结果呈现或挑选的规则登记进账本 |

## 2. 六条不变量

### K1 身份恒定

**条文**：角色核心设定只读。每一条与角色有关的账本记录都携带当时的身份指纹。核心设定只能通过显式的“身份修订”事件改变，修订本身也是账本记录，且只能由持有 `profile:write` 的 actor 发起。

**理由**：观众和用户信任的是“同一个角色”。没有指纹，人设漂移只能靠感觉发现；有了指纹，漂移就是一条可以检出的记录。

**可断言**：
- 对话路径无法改变身份指纹。
- 任意两条记录的指纹不同，二者之间必然存在一条身份修订事件。
- 动机、心情、关系等可变状态的变化不影响指纹。

### K2 意图不等于事实

**条文**：只有登记过的权威能签发事实。意图无论内容写了什么（包括自称“已完成”“系统确认”），都不能被转换成事实。事实必须引用它所回应的意图（若有），并标明签发的权威。

**理由**：这是 CL-World 三平面设计的通用化。模型可以想、可以说、可以提议，但“发生了什么”只能由规则说了算。

**可断言**：
- 不存在没有权威签名的事实记录。
- 权威名单不能由对话内容、模型输出或世界回执里的自由文本扩展。
- 一个意图最多被一个事实结算；重复结算被拒绝并留痕。

### K3 只增不改

**条文**：所有影响角色的记录都写入账本，账本只追加。每条记录包含前一条记录的哈希，篡改、插入、删除都能被检出。删除和更正以新记录的形式追加（墓碑、更正事件），不改动旧记录。

**与“被遗忘的权利”的关系**：账本对**内容的哈希**成链，内容本体可以单独存放。用户要求删除时，可以擦除内容本体，追加一条墓碑记录；链条仍可校验，删除这一行为本身留痕，但被删的内容不再可读。

**可断言**：
- 修改任意一条历史记录后，链校验失败，并指出第一条断开的位置。
- 任何拒绝（权限、准入、策略）都对应一条账本记录。
- 擦除内容本体后，链校验仍然通过。

### K4 可复现

**条文**：规则层面的随机性只能来自账本开头登记过的种子流。模型的生成结果不可复现，因此模型的原始输出必须完整记入账本；复现指的是**依据账本重放**，而不是重新生成。

**理由**：公开种子与原始输出，任何人都能验证“规则没有被暗中调整”。

**可断言**：
- 给定同一份账本，重放得到逐条相同的事实序列。
- 影响判定与结算的代码中不存在未登记的随机来源（例如直接调用 `Math.random`）。只用于生成标识符的随机数不在此列，现有的 `EntropyIdFactory` 不违反本条。
- 种子流可以公开，但不能用于推导承诺用的 salt（见 K5）。

### K5 承诺–揭示

**条文**：需要暂时对某些读者隐藏的内容（例如角色的封存心声），只能以承诺的形式进入公开记录，并附带揭示期限。揭示时公开 salt 与原文，任何人可以重算校验。salt 必须来自密码学随机数，不能从公开种子推导。

**可断言**：
- 揭示的原文与承诺不符时，揭示被拒绝并留痕。
- 期限已过仍未揭示的承诺可以被列出，属于违规。
- 公开记录中不出现封存内容的原文或可还原它的信息（包括动机标签）。

### K6 预先登记

**条文**：任何会影响“结果如何呈现”或“哪个结果被选中”的规则——心声分级比例、挑局评分、剪辑可用的筛选条件——必须在第一个结果产生之前登记进账本。依据规则作出的决定必须引用已登记规则的哈希。换规则只能登记新版本，并且只对之后的结果生效。

**理由**：只遮不编、只藏不改还不够；如果可以看完结果再决定遮什么、选哪一局，同样是在写剧情。

**可断言**：
- 任何可见性决定都引用一条在结果之前登记的规则。
- 结果产生之后登记的规则，对已有结果的引用被拒绝。
- 未被选中的结果仍留在账本中，不会消失。

## 3. 修宪

1. 内核条款只增不减。修改条款时提升版本号，账本开头记录宪法版本与本文的哈希。
2. 新增条款必须同时给出可断言的测试；写不出断言的原则不进内核，放到世界层或设计文档。
3. 世界层可以声明比内核更严格的规则（例如“夜会话心声一律明文”），不能声明例外。

## 4. 内核与世界层的边界

以下内容**不属于**内核，由各个世界自己定义，但必须遵守 K1–K6：

| 世界层内容 | Free Roam 中的例子 | 受哪条内核约束 |
|---|---|---|
| 世界观与主持角色 | 罐、罐主 | K2：罐主也只是权威之一，不能绕过规则改判定 |
| 资源与胜负 | 米粒、名望 | K2、K4 |
| 角色取材与能力 | 神兽、雷鼓、幻形 | K1：能力写在核心设定里；K2：能力由规则引擎判定 |
| 表现形式 | 双镜头、罐相突变 | 不受内核约束 |
| 心声的分级与揭晓节奏 | 明文、遮蔽、封存 | K5、K6 |
| 挑局与剪辑 | 每期跑 3 局挑 1 局 | K3：未选中的局留存；K6：评分规则预先登记 |
| 入戏与出戏 | 每季限量出戏 | 世界层规则 |
| 观众参与 | 虚拟币押注 | K2：押注结果由权威结算 |

## 6. 实现顺序建议（不在本版实现）

1. **K3 账本**：其余各条都要往账本里写，先有账本。
2. **K1 指纹**：改动最小，规范化 `CharacterProfile` 后取哈希即可。
3. **K2 通用化**：把 CL-World 的权威与回执抽象成“登记权威 + 签发事实”。
4. **K4、K5、K6**：Free Roam 的第一期引擎里已有可参考的原型（种子流、`sha256(salt|原文)` 承诺、开赛前确定的分级规则），可以向内核收敛。

## 8. 实现对照（V0.6）

代码在 `src/kernel/integrity/`，入口是 `Integrity` 类；所有「可断言」都写成了测试
（`tests/kernel/integrity.test.ts`，SQLite 部分在 `tests/cross_session/ledger.test.ts`）。

| 条款 | 实现 | 接入 |
|---|---|---|
| K1 身份恒定 | `identityFingerprint`（规范化 JSON 的 sha256）；`reviseIdentity` 要求 `profile:write`，修订记录携带新指纹；`checkIdentityContinuity` 检出无修订的指纹变化；恢复时人设与账本不符 → `IDENTITY_DRIFT` 拒绝记录 | `AgentCore.replaceProfile` 自动写身份修订；每条审计镜像都带指纹 |
| K2 意图≠事实 | `registerAuthority` 要求 `policy:write`，返回不可伪造的凭据对象；`issueFact` 只认凭据、校验范围；一个意图最多一个事实 | 自主循环：准入时登记意图（引用世界动作 id），世界回执与观察由桥以世界权威签发为事实 |
| K3 只增不改 | `Ledger`：记录头哈希链 + 内容哈希；`erase` 擦内容本体并追加墓碑；`verifyChain` 指出第一条断开处；内容缺失且无墓碑也算断开 | 审计事件全部镜像进账本（任何拒绝都是一条记录）；SQLite 新表 `ledger`（§7 问题 1 的决定：新建表，`events` 不动）；恢复流程第 4 步核对哈希链 |
| K4 可复现 | 种子流必须在第一条事实之前登记；字符串种子算法与《罐中斗》第一期引擎逐位一致；`recordModelOutput` 完整记录模型原始输出 | 自主循环把 LLM Mind 的原始输出入账；文字箱庭的世界随机源改为登记过的种子流 |
| K5 承诺–揭示 | `sha256(salt\|原文)`，salt 来自 `randomBytes`；账本只写校验码与期限；揭示不符拒绝并留痕；`overdue` 列出逾期 | 由世界层调用（Free Roam 的封存心声） |
| K6 预先登记 | `registerRule` 版本化、规则哈希；`decide` 要求规则早于所有被引用的结果；结果可以是事实、意图（例如一条心声）或模型原始输出 | 由世界层调用（心声分级比例、挑局评分） |

**K4 与 K5 的协调**：K4 要求模型原始输出完整入账，而原始输出里可能有尚未揭示的封存心声（K5 不允许出现在公开记录里）。
实现上两条同时成立：模型输出记录的内容里带一个密码学随机 nonce（公开的内容哈希无法被穷举还原），
公开版账本（`publicExport()`）扣下这类记录的内容本体，只公开链与哈希；私有版保留全部原文，供复现与到期揭示核对。

§7 其余未决问题（身份修订入口、多世界权威命名空间、擦除后的派生数据）仍然开放。
