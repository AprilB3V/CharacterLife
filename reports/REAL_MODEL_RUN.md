## 5. 运行后诊断（跑完之后才做的，属于同一实验的一部分）

主实验 14 次调用里有 **5 次记录的 `reply` 为空**（A/t2、A/promise、A/persona、
B/promise×2、B/persona），但 completion tokens 分别是 23/41/39/49/118 —— 明显生成过内容。
空回复会让「B 是否记得约定」这一项无法判定，所以补做了诊断。

### 5.1 根因（1 次调用定位 + 2 次调用复现）

同一个探针单独发时返回正常（440 字，内容正确）。受控复现（先问书、再问约定）抓到了原始响应：

```
[调用 2] text.length=51 finish=stop reasoning=0 usage={"promptTokens":1341,"completionTokens":51}
  raw: "                                                   "   ← 51 个空格
结果 reply(0) = ""
```

**结论：模型有时会返回纯空白内容（finish_reason=stop，content 是 51 个空格）。**
这不是引擎解析错误，也不是上下文超限，而是模型输出本身的问题。
但**引擎把空白原样透传成空气泡，这是产品的真实缺陷**。

### 5.2 修复

`ConversationService` 增加空白回复降级：`reply.trim().length === 0` 时替换为
「嗯……刚才那句我没接住。你再说一遍，好吗？」并写 `provider_error` 审计
（含 rawLength / finishReason / reasoningChars 便于复现）。回归测试：
`tests/conversation.test.ts` →「模型返回纯空白内容时改用降级台词，不返回空气泡」。

### 5.3 对第 3 节结论的修正

- 「约定」探针在主实验里因空白回复而无效；诊断调用中 B 组**确实回忆出了约定**：
  「记得。你父亲留下的那本《陶庵梦忆》，被水泡过。约的是今天下午，两点到五点之间。
  我昨天写在便签上了，压在台灯底下。」
  因此 B 组的记忆召回应记为 **书 ✅ / 约定 ✅（诊断调用验证）**。
- A 组的三次空白同理，属于同一个模型输出异常，不代表 A 组「记得更好或更差」。
  A 组真正的问题是捏造，见下一条。

### 5.4 一个比空白更重要的发现：A 组会捏造记忆

A 组在**新会话**（聊天记录已清空）里被问「你还记得我说的那本书吗」时回答：

> 「记得。你说的是那本封面掉了、书脊也散了的**《城南旧事》**。我把它放在靠窗那张工作台上，
> 先拆了线，纸页上的霉点用软毛刷一点点清的……」

而用户从没说过《城南旧事》，原书是**被水泡过的《陶庵梦忆》**。
这是典型的「为了接话而编造共同经历」——恰好是本项目要解决的问题 4。
B 组在同一时刻回答的是《陶庵梦忆》+ 水泡 + 约定时间，信息来自 SQLite 检索，不是聊天记录。
