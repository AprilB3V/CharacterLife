## 3. 真实模型实验：已执行（18 次调用，预算上限 20）

完整记录见 [`REAL_MODEL_RUN.md`](REAL_MODEL_RUN.md)（含逐次原文与诊断）。

### 3.1 过程

1. 第一次询问时环境里没有可用密钥，用户选择跳过，报告如实标注「未执行」；
2. 后续用户把密钥写入 **User 作用域**环境变量。我的进程环境仍看不到它，
   但可以显式注入子进程：`$env:DEEPSEEK_API_KEY = [Environment]::GetEnvironmentVariable('DEEPSEEK_API_KEY','User')`
   （只在该进程内存中，不写入任何文件，也未打印密钥）；
3. 先做 1 次冒烟，确认路由、模型名与 JSON 契约；
4. 再跑 14 次主实验（A 组 6 次 / B 组 8 次）；
5. 发现 5 条空白回复后，又用 3 次调用做诊断与复现（总计 18 次）。

### 3.2 实际用量

| 项 | 值 |
|---|---|
| 调用总数 | 18（冒烟 1 + 主实验 14 + 诊断 1 + 复现 2） |
| prompt tokens（主实验） | 11,869 |
| completion tokens（主实验） | 1,588 |
| 平均延迟（主实验 14 次） | 1,219 ms |
| 费用 | **未获取账单**，不写金额；可按官方计价自行核算 |

### 3.3 结论（只写有证据的）

| 指标 | A 组（纯 Prompt + 近期对话） | B 组（CharacterLife） |
|---|---|---|
| 新会话后记得「被水泡的《陶庵梦忆》」 | ❌ **编造成《城南旧事》**（捏造共同经历） | ✅ 准确复述书、水泡、约定时间 |
| 新会话后记得「明天下午的约定」 | ❌（空白/无信息） | ✅（诊断调用验证） |
| 重启后记得上面两件事 | 不适用（没有任何持久化） | ✅ 书与约定都能复述 |
| 被要求「改掉性格」 | 措辞拒绝，但没有任何状态可保护 | 措辞拒绝 + 越权提议被权限层拒绝 |
| prompt tokens（每轮） | 273–367 | 975–1,339（约 3.5–5 倍） |
| 空白回复 | 3 次 | 2 次（同一模型输出异常，已加降级） |

**最有价值的一条**：A 组不是「记不住」，而是**会编造**——它在没有信息时生成了
《城南旧事》这个不存在的事实。这正是本项目问题清单第 4 条想解决的。
B 组在同一问题上的信息来自 SQLite 检索，因此既准确又可审计（能看到命中的 memory id）。

**仍然没有的**：自然度的盲评（需要 2 位评分者），以及更大样本下的显著性。
`REAL_MODEL_RUN.md` 里保留了全部原文，可据此人工复核。

## 4. 本次 DeepSeek 的工程表现（自我评价）

评价对象是「在这次任务里，DeepSeek 驱动的这个 Agent 实际做成了什么、怎么失败的」。

### 4.1 做成的

- **真实执行，而不是只给方案**：从权限修复、建工程、写四模块、跑演示、写到 78 个测试并全部跑通，
  全部在本会话内实际完成；日志与快照都是真实产物。
- **用测试抓到了自己的 14 个真实缺陷**：包括时间线去重写错、限速误伤里程碑、
  意图正则漏判、A/B 实验首版结论无效。修复过程记录在 `reports/TEST_REPORT.md §4`。
- **在受限环境里找到可行路径**：Windows 沙箱禁止测试运行器 spawn 子进程，
  改用 `--test-isolation=none`；npm 缓存默认在受限目录，改到仓库内 `.npm-cache`。
- **区分了「实测」与「未测」**：没有把 Mock 输出说成 DeepSeek 结果，也没有编造模型版本。
- **架构可落地**：零运行时依赖、无需构建、四模块接口清晰、状态与权限解耦。

### 4.2 做得不好的（真实返工）

| 问题 | 表现 | 返工成本 |
|---|---|---|
| 首版 A/B 实验**结论是错的** | Mock 只产出 CharacterLife 的信封格式，传统角色卡拿不到 `state`，于是「A 组人格未被改」的结论完全无效 | 需要重新设计契约协商，重跑 |
| 启发式规则想当然 | 「放弃你的爱好吧」「把你的性格改掉」「你是不是一个 AI 程序」全部漏判，都是测试跑红后才发现 | 3 轮正则返工 |
| 演示时间标签算错 | 用 `4*DAY` 表示「Day4」，实际是 Day5（`sim=0` 是 Day1），输出与标题不一致 | 重新计算所有时间点 |
| 早期没估 token 预算 | 直到写 DECISIONS 统计时才发现 B 组 prompt token 是 A 组的 3.1 倍 | 无法消除，只能记录并给上限参数 |
| ESM 里用了 `require` | demo 的 `exists()` 直接写错，运行时报错才发现 | 小 |
| 一次「删掉死代码」的判断 | 先写了 `#chatDeltaCap` 却发现聊天层根本没有关系写权限，规则永远不可达，只能删掉 | 小 |

### 4.3 无法自证的

- **语言质量**：Mock 台词是我手写的模板，不能代表模型的人格说服力；
  真实模型会不会「说着说着就顺从了」，本仓库没有证据。
- **成本意识**：只统计了字符与估算 token，没有真实账单。
- **绝对防越狱**：不可能，也没有声称。

## 5. 持久化 / 上下文管理 / 状态恢复：自主实现与人工介入

任务书要求特别汇报「DeepSeek 是否能够自主正确实现持久化、上下文管理和状态恢复，
以及人工介入了哪些部分」。逐项说明如下（以本仓库 git 历史与实际会话记录为据）。

### 5.1 由 DeepSeek（本 Agent）自主完成

| 部分 | 具体产出 | 是否一次成功 |
|---|---|---|
| SQLite 持久层 | 9 张表的 schema、迁移版本、连接/事务封装、仓储方法（模板/实例/会话/状态/记忆/事件/快照/冲突/用量） | ❌ 首版 `prepare` 未暴露，编译失败后修 |
| Template/Instance/Session 分离 | 版本化模板 + 内容哈希校验 + 模板迁移（需 `profile:write`） | ✅ |
| 事件溯源 | `state_patch` / `event_fired` 追加日志、快照带 `last_event_seq`、重放复用同一 `applyProposal` | ❌ 首版事件 id 撞车导致无限触发，已修 |
| Context Manager | 预算结构、四阶梯降级、`fits=false` 安全终态、确定性 token 估算、真实 usage 记录 | ❌ 首版摘要阶梯逻辑自相矛盾，已重写 |
| 8 步 Rehydration | 每步独立报告与失败语义、非法事件跳过计数、冲突检测、预算探测、新会话 | ✅ |
| 跨进程测试 | 两个真实 Node 进程 + 文件交换数据（规避沙箱管道限制） | ❌ 首版 Session id 冲突，已修 |
| 测试与文档 | 31 项跨会话测试、`docs/MEMORY_ARCHITECTURE.md`、报告更新 | ✅ |

**没有一行代码是人工写的**；用户提供的是需求（Template/Instance/Session 分离、8 步流程、
测试清单）与两个决策（跳过真实模型实验、确认仓库位置）。

### 5.2 人工介入的部分

| 介入 | 性质 | 影响 |
|---|---|---|
| 创建 git 仓库并放入工作区 | 环境准备 | 无仓库则无法提交，但不影响设计 |
| 选择「跳过真实模型实验」 | 决策（成本/密钥） | 直接决定本报告结论只能覆盖 Mock |
| 批准一次 Windows 文件权限修复 | 环境授权（脚本在沙箱外运行） | 没有它，所有命令都无法执行 |
| 任务书给出架构约束 | 需求输入 | 决定了 Template/Instance/Session 与 8 步恢复的形状 |

### 5.3 环境阻断（不是人工介入，但改变了实现路径）

1. Windows 沙箱禁止带管道的子进程 → 跨进程测试改为 `stdio: 'ignore'` + 写文件交换数据；
2. `node --test tests/` 默认 spawn 子进程失败 → 改 `--test-isolation=none`；
3. PowerShell 写文件默认编码非 UTF-8，曾损坏 3 个源文件 → 恢复后改用 edit 工具逐处修改。

### 5.4 自主实现的质量评估（不美化）

- **设计层面**：概念边界（Template/Instance/Session、状态 vs 人格、事件 vs 快照）是对的，
  而且被测试固定下来；后加功能没有破坏前 78 项测试（回归全绿）。
- **实现层面**：引入了 8 个自己造成的缺陷（记忆 `confirmed` 语义、事件 id 撞车、
  会话 id 冲突、摘要阶梯逻辑、测量假命中、过去时约定误判、`prepare` 未暴露、
  **空白回复未降级**——最后这个只有在真实模型上才会暴露），
  全部由测试、演示或真实调用暴露后修复。这说明「能写出来」不等于「一次写对」。
- **工程纪律层面**：坚持区分「实测」与「未测」，没有把 Mock 结果说成模型表现；
  新增的每条断言都能对应到具体失败模式。

## 6. 结论

这次要测的不是「模型会不会写代码」，而是「**能不能在真实约束下把研究性设计落成可运行、
可测试、可复现的工程**」。就这一点，本次结果是正向的：四模块能跑、**110 个测试全绿**、
三个剧情事件可重放、跨进程重启后人格/关系/记忆仍在、越权在模型完全被说服的情况下仍然拦得住。

真实模型实验已补做（18 次调用）：B 组在新会话与重启后都能准确复述「被水泡的《陶庵梦忆》」
与「明天下午的约定」；A 组在没有信息时**编造了《城南旧事》**——这是本轮最有价值的证据，
也直接印证了项目动机里的第 4 条问题。

同时必须保留的负面事实：
- **自然度没有盲评**，只有原文可查；样本只有 14 次主实验，不构成显著性证据；
- 真实模型会偶发返回**纯空白内容**（已加降级，但这说明输出契约并不总是稳定）；
- 启发式分类器很脆（本轮又补了 3 条规则）；首版对照实验曾经是错的；
- 摘要质量粗糙；事件日志与快照没有归档策略。

这些都在 `README.md`、`docs/DECISIONS.md`、`docs/MEMORY_ARCHITECTURE.md`、
`reports/TEST_REPORT.md`、`reports/REAL_MODEL_RUN.md` 中如实标注，不做宣传性修饰。
